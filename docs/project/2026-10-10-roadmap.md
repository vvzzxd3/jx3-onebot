# 项目路线图

## 1. 项目方向与当前边界

项目是面向 QQ 的 Python IM Bot 服务端，业务方向为剑网 3 查询，仅服务 QQ。唯一受支持入口直接使用 QQ 官方机器人 API v2，不新增多平台或 OneBot 兼容；旧 NoneBot2／OneBot 入口、插件与依赖已从工作树清理。

官方 WebSocket／HTTP 回复、天气首功能、`开服 服务器名称` 查询及已批准的四表双向聊天数据库已完成离线实现。**真实 QQ／天气联调、部署机网络验证与正式生产切换仍待完成**；代码清理不代表旧进程已停止，离线实现不代表平台验收通过。当前功能与使用方式见 [项目 README](<../../README.md>)，运维步骤见 [部署指南](<../qq-integration/2026-10-10-deployment.md>)。

长期目标保留为 **2027 年 1 月完全替代萌萌**，具体切换日、功能范围及验收门槛待确认。尚无经过验证的完整剑网 3 查询命令清单；旧 AI／复读／爬虫未迁移，不能把天气、接入或聊天数据库完成等同于业务替代完成。

## 2. 已批准的聊天数据库边界

1. 会话就是聊天记录集合，不建外部身份映射、单聊会话容器或群聊会话容器。
2. 独立用户、群、单聊消息、群聊消息四张业务表，OpenID 按 AppID 隔离；用户在群／单聊的相同 OpenID 定位同一记录。
3. 单聊外键为 `user_id`。机器人消息在 QQ 确认成功后才插入聊天历史，与 outbox sent 同事务提交后输出发送日志；发送前不预建聊天行，失败／过期／不确定仅属 outbox 与诊断。QQ 成功后本地落库失败不重发，不伪造成功归档日志。
4. 入站顺序为统一解析 → 消息／待处理任务／可靠水位同事务落库 → 聊天日志 → 匹配器／业务。两类消息均无独立 @ 标识字段，保留事件来源；`to_me` 只属于运行时匹配上下文。
5. 支持的群聊／单聊消息默认永久归档，不设聊天开关、授权白名单或自动保留期限。手动遗忘仅逻辑删除，不能保证清除 WAL／备份，也不能恢复此前已删除正文。
6. 迁移与恢复必须保护天气预算、偏好、城市、缓存及可靠收发状态；不因聊天模型调整重建共享库或清空传输队列。平台权限、备份及日志治理仍须处理，不恢复个人号监听。

## 3. 工作优先级与实施授权

| 工作 | 内容 | 状态与下一步 |
| --- | --- | --- |
| 官方接入与天气 | 权限、事件接收、HTTP 被动回复、Resume、城市输入与天气额度 | 已有离线实现；按[部署指南](<../qq-integration/2026-10-10-deployment.md>)完成授权联调和部署验收 |
| 聊天数据库 | 四表、双向消息、提交后日志／业务与成功发送归档 | 已获批准并完成离线实现；验证真实群聊／单聊、全量／@双投和本应用发送回投行为 |
| 运维准备 | 一致性备份、WAL／日志隐私、资源监控、退出告警与切换 | 部署前落实；不把代码或文档完成写作上线成功 |
| 多实例／多 AppID | 独立实例隔离与共享天气预算治理 | 仅登记待办，方案与排期待确认，未批准立即实施 |
| 后续游戏业务与替代 | 除已离线实现的开服查询外，补齐功能清单、群内对照、试运行与差异处理 | 后续重新规划，不编造功能范围或未经确认的排期 |

多实例待办要求隔离各应用的配置、Token、WebSocket／Resume、数据库、待处理消息／回复与用户偏好；同一天气项目须统一预算管理或保守分配额度并保留历史计数，避免每个实例重复获得完整额度。后续需补共存、故障／重启、无跨应用误投递与预算并发验证。需求与讨论统一从 [Agent 需求索引](<../../.agents/notes/INDEX.md>)进入，**不代表已实现或授权立即开发；当前暂不处理 AppID 更换，不修改数据库绑定或现有数据**。

## 4. 联调与长期替代验收

- 在明确授权及运维准备后，验证实际应用权限、DNS／TLS／动态 WSS、天气供应商响应与部署机出站能力；不因公开 IPv6 地址或群主开关推断应用已具备经验证的全部能力。
- 验证群全量／@事件、单聊、实际内容和名称字段、双投去重及本应用发送回投；确认回复目标与收发归档顺序，不自动重发不确定的发送。
- 切换前确认旧进程退出、无重复回复，保护月预算和未完成传输状态；旧功能中断须获接受，不宣称等价迁移。
- 完全替代须经维护者确认功能范围、QQ 端到端行为、群内对照／试运行、差异与切换条件。天气首版、数据库建表或离线测试均不能替代完整游戏功能验收。
