## 1. 当前事实、目标与非目标

当前运行代码仍是 旧 NoneBot／OneBot 入口（历史路径 `bot.py`，已清理）。本轮检查了工作区、现有文档、依赖及旧天气处理器；保留原有暂存／未暂存／未跟踪内容，不导入会加载凭证或连接服务的旧插件。

目标：依据用户确认方向建立独立 QQ 接入层，首功能提供城市输入到每日预报的链路；本地保存范围、额度计数周期及安全边界明确后再实现。

非目标：本次调研不连接 QQ、不获取访问凭证、不请求天气数据、不保存真实城市／个人信息，不删除旧框架或改动敏感配置，不新增多平台／OneBot 兼容。

## 2. 已确认方向

1. 优先 QQ 官方 WebSocket 主动出站连接，不要求开放公网 HTTP 回调；事件接收接口与业务分发分离，保留以后替换 Webhook 的代码边界，但首版不实现两套接入。
2. 面向 `GROUP_MESSAGE_CREATE` 全量模式及 `GROUP_AT_MESSAGE_CREATE`；群主需在客户端开启接收所有消息。普通聊天不入库、不触发天气查询；不因为全量可达就实现全量聊天归档。
3. 首项上线功能是天气，不再按上轮建议先选择剑网 3 查询；其他插件是否迁移另行确认。
4. 使用维护者指定的 GeoAPI 城市搜索与当前每日天气预报接口。

## 3. 官方资料揭示的关键差异

- 和风天气 [定价](https://dev.qweather.com/docs/finance/pricing/) 明确自然月价格累进，天气和基础服务（含 GeoAPI）每月合计首 50,000 次免费。不能把每日 50,000 次上限写成“保证免费”。
- [每日天气预报](https://dev.qweather.com/docs/api/weather/weather-daily-forecast/) 当前接口是 `/weather/v1/daily/{latitude}/{longitude}`，非城市 ID 接口；需使用搜索返回或其他获准来源的坐标。旧城市 ID v7 接口不是用户指定接口，不应默默换回旧实现。
- [GeoAPI 使用限制](https://dev.qweather.com/docs/terms/restriction/#cache-or-index-geoapi-data) 与 [FAQ](https://dev.qweather.com/help/#can-i-cache-data) 的缓存措辞宽窄不同，但 FAQ 明确不能缓存地理信息／创建索引。用户主动输入不等于 API 返回地理数据库，不能默认将 GeoAPI 结果建成本地城市索引。

## 4. 建议执行步骤与验收

1. 用户已确认每自然月不超过50,000次免费份额并选择先评估城市库。前置评估已完成；选择最终城市源／确认授权，再开展实现，不再询问已明确的日／月口径。
2. 首版使用官方 WebSocket、单体 Python 异步服务、独立 QQ 事件接入接口；获授权后验证凭证、API Host与出站网络，不在文档核查中连接服务。
3. 依照已批准城市源实现命令、消歧、输入偏好保存／删除、每日预报和归因；GeoAPI即时兜底默认不持久化其返回字段，本地优先仍为建议。
4. 建立所有和风请求统一月预算：请求前持久化占位、原子计数、缓存命中不调用、失败／重试保守计数、重启不清零，并扣除初始已用量和其他项目份额。
5. 后续以模拟传输、合成事件和临时数据库验证断连／重投／重复消息、同名、解析、缓存、预算与重启；本轮只有评估，不声称测试已通过。
6. 授权群试运行通过后切换，停止旧链路重叠发送；正式清理旧依赖为后续任务。

## 5. 风险与待确认项

- 月度免费预算已确认；初始已用量、账单月时区和同帐号其他调用尚需确认。只管本服务计数不能保证整个帐号不超额。
- 本地城市源评估已完成：和风公开列表技术匹配但本地使用／分发授权范围未完整明确；GeoNames开放许可明确但中文覆盖、坐标与区县样本未验收。最终选择仍待维护者确认，GeoAPI回包默认不落库。
- 公网只有 IPv6 不代表没有 IPv4 出站；如纯 IPv6 出站，官方域名与实际网关的可达性须在部署环境验证。不得承诺 WebSocket 一定可连接。
- 群全量平台能力／群主开关已由用户确认，但当前应用的真实接收、身份与回复路径未实测。
- 天气免费额度用完不会天然停止平台后付费，因此必须实现主动熔断；新凭证不得复用仓库已知有泄露风险的存储方式。
