## 2. 官方资料核实（2026-10-10）

以下是实际访问的官方文档所述能力，不是对当前账号权限或运行行为的实测结论。资料今后可能调整，实施前应再次核对。

| 主题 | 文档所述事实 | 本项目影响／尚待验证 |
| --- | --- | --- |
| 准入与凭证 | 创建官方机器人获得 AppID、AppSecret；旧 Token 鉴权已弃用 | 维护者确认账号主体、机器人状态、群能力与生产审核条件；不得继续使用个人号登录凭证 |
| API 鉴权 | 通过 `POST https://api.bot.qq.com/app/getAppAccessToken` 获取 access_token；API Header 为 `Authorization: QQBot {access_token}` | 服务端缓存、刷新并避免并发重复获取；凭证不进入日志或仓库 |
| Token 时效 | `expires_in` 表示有效秒数；默认 7200 秒，接近过期 60 秒内可获取新值 | 以实际响应管理过期时间，在刷新窗口刷新，不硬编码“任意时刻请求就会得到新 Token” |
| Token 错误 | 获取 Token 失败时 HTTP 仍可能为 200，通过响应体 `code` 判断业务错误 | 不能只调用 `raise_for_status()` 就认为鉴权成功 |
| API 域名与身份 | 统一域名 `api.bot.qq.com`；group_openid／member_openid 等身份与应用关联 | 旧 QQ 群号、QQ 用户号不能直接充当官方身份；不假设可跨应用或跨场景直接关联 |
| Webhook | 支持 HTTPS 回调，允许配置端口 80、443、8080、8443；含回调地址验证 | 建议外网 443，由反向代理转发内部 ASGI 服务；公网可达、证书和后台配置须验证 |
| 回调安全 | 使用 Ed25519，签名原文为时间戳 + 原始 HTTP Body；密钥种子按官方 Bot Secret 规则派生 | 不重序列化 JSON 后验签；不复用仓库中的天气 JWT 私钥 |
| WebSocket | 当前官方文档仍提供网关连接、鉴权、心跳、重连与 Resume | 不依据旧文章断言“已停用”；如无法部署 Webhook，可在账号实测可用后评估，首版不同时实现两套接收链路 |
| 群 @ 消息 | `GROUP_AT_MESSAGE_CREATE`，群与单聊事件 Intent 为 `1 << 25`；content 已去掉 @ 机器人前缀 | 最小闭环使用此事件；不混用频道 AT_MESSAGE_CREATE 或频道 Intent |
| 群全量消息 | `GROUP_MESSAGE_CREATE`：开启“接收所有消息”后，群里的每条消息不限于 @ 都推送；字段与群 @ 消息一致 | 文档能力存在，但当前应用是否可开启、实际事件接收范围须测试；不自动启用全量采集 |
| 群消息发送 | `POST /v2/groups/{group_openid}/messages`；被动回复 msg_id 来自事件 `d.id` | 顶层事件 id 与消息 id 不是同一概念；event_id 仅用于接口列出的支持回复的事件 |
| 回复与限流 | 群被动回复有效期 5 分钟，每条最多回复 5 次；主动消息另有认证类型、Bot／群频控及每日上限 | 长任务、分段回复与重试必须计入预算；接口标注 100 QPS 不等于可以绕过主动消息频控 |
| 富媒体与去重 | 富媒体先上传获取 file_info；被动回复相同 msg_id + msg_seq 重复发送会失败 | 重写 OneBot MessageSegment 发送；同一次发送重试保持相同序号，不用新序号掩盖不确定结果 |

## 3. 切换的本质：替换三层职责，而非只换适配器

```text
现状：QQ → 个人号独立客户端 → OneBot V11 → NoneBot2 → 插件 → 原路回复
目标：QQ 官方平台 → 官方事件入口 → 指令分发 → 业务服务 → QQ 官方 OpenAPI
```

| 旧职责 | 新职责 |
| --- | --- |
| 个人号客户端登录／收发 | 官方机器人身份、应用授权与官方平台事件 |
| OneBot 事件、CQ 码、群号与消息段 | QQ 官方事件模型、OpenID、官方文本／富媒体请求 |
| NoneBot 生命周期与配置 | ASGI lifespan、显式配置与服务资源管理 |
| on_command／on_message／规则／优先级 | 本项目显式命令表、事件筛选、权限与路由规则 |
| Matcher.send／finish | 业务返回结果，由 QQ 发送模块发送；结束处理是普通控制流 |
| 插件配置／日志／会话 | 配置模型、结构化脱敏日志、按官方身份分隔的会话状态 |

换成 NoneBot 的 QQ 适配器只能替换 OneBot 接入，仍保留 NoneBot，不满足已确定目标；自行把 QQ 事件翻译成 OneBot 也继续保留旧协议耦合，不建议作为本项目终态。

## 4. 建议目标设计（尚未批准／实现）

### 4.1 单体服务优先

建议 Python 3.12 + FastAPI／Uvicorn + httpx + Pydantic 配置模型 + cryptography（Ed25519）作为首版。第三方包需在实现时选择兼容版本并明确直接依赖，不沿用旧依赖清单作为新约束。

首版只选择一种事件入口，推荐 Webhook；不先拆微服务、不搭通用适配层、不要求 Redis／消息中间件才能完成闭环。官方 SDK 可参考，但先核查其版本对当前群事件、回调及域名的支持，不能因官方推荐示例而假设覆盖全部新能力。

```text
HTTPS 反向代理
  └─ QQ Webhook 入口（地址验证、原文验签、应用校验、大小限制）
       └─ 事件解析 + inbox 去重／短期持久化
            ├─ 返回平台 ACK（不等待游戏接口／AI）
            └─ 受控 worker / dispatcher
                 ├─ 指令解析与权限检查
                 ├─ 剑网 3 查询等业务服务
                 └─ reply / outbox → QQ API client → 官方平台
```

持久化建议：单实例低流量可用 SQLite 的 inbox／outbox 最小实现；多实例或需要并发写入时选择 PostgreSQL。Redis 仅在确有共享缓存、跨实例锁或队列需求时引入。最终选型需结合部署与保留期限确认；当前没有这些实现。

### 4.2 建议代码边界

以下均为拟议路径，尚未创建：

```text
src/jx3_bot/
  app.py                 # 应用生命周期、健康检查、入口装配
  settings.py            # 显式配置，不依赖 get_plugin_config
  qq/
    webhook.py           # 地址验证、回调 ACK、验签后接收
    signature.py         # Ed25519 与原始字节校验
    models.py            # 官方事件与回复上下文
    token.py             # access_token 缓存、刷新和并发控制
    client.py            # 官方请求、错误码、trace_id、限流
    media.py             # 仅在富媒体需求确定后增加
  commands/
    router.py            # 命令／别名／参数解析、处理器显式注册
    handlers.py          # 首版帮助／测试闭环；按需求再拆模块
  services/
    jx3.py               # 游戏 API 访问与查询业务，不接收 NoneBot 类型
  storage/
    inbox.py             # 重投去重、处理状态与故障恢复
    outbox.py            # 回复计划、稳定序号和发送结果
 tests/                  # 实际实现时创建，合成／脱敏样本
```

不机械地把旧 plugins 改名后继续动态加载。处理器是普通异步函数：输入解析后的参数／必要上下文，返回文本或明确的回复结果；真正发送集中到 QQ 模块。只有需求确认后的服务才注册，避免未完成插件在导入时阻断启动。

### 4.3 关键处理规则

1. **回调与安全**：保存原始请求字节用于验签，区分 op=13 地址验证与 op=0 事件，检查应用身份与请求大小；按官方要求处理握手。任何握手例外须独立限制，不能令普通事件绕过验签。
2. **密钥**：QQ Bot Secret 与天气 JWT 密钥分离，使用环境／部署密钥注入；不保存 Token、签名密钥、message_scene.ext 的 auth_token、带鉴权参数附件 URL 或原始群聊到普通日志。
3. **重放与重投**：签名时间策略结合实际重投窗口配置，不能用任意的过严时间窗口拒绝合法重投；事件身份与业务消息身份分别去重，保护重启和并发场景。
4. **去重建议**：应用范围内的顶层事件 id（如存在）作事件键；群消息用 AppID + group_openid + d.id 作业务键，兼容 @／全量事件重复覆盖；只有样本确认具有语义需要时才纳入真实入站序号，不以网关 s 代替全局身份。
5. **先可靠接收，再 ACK**：仅在必要事件数据已短期持久化后返回成功 ACK；恢复 worker 可接续 accepted／processing 状态。只使用内存队列或 BackgroundTasks 后立刻 ACK，会有重启丢任务风险。文档闭环演示若暂用内存，必须明确不能按生产可靠性验收。
6. **最小持久化**：只保存处理所需字段，设短保留期与删除流程；业务请求参数可能敏感，限制访问。非业务聊天默认不进任务存储，不无限期归档整个回调。
7. **命令入口**：初期用 `@机器人 帮助`／`@机器人 测试`，命令本身仍可不要求 `/`。解析器明确去空白、命令别名、参数边界及可选 `/` 策略，不默认复制 NoneBot 优先级与 block 规则。
8. **业务分流**：命令路由排除机器人发送内容，避免循环。
9. **会话身份**：按 AppID + 场景 + group_openid（群场景）+ member_openid／user_openid 分隔；不直接搬运旧 QQ 号会话，不把不同群的 AI 上下文混用。
10. **回复预算**：把 d.id、群 OpenID、时间与出站序号带入回复上下文；在 5 分钟／5 次限制内规划正文、进度提示与错误提示。过期不能静默去掉 msg_id 改成主动推送。
11. **发送状态**：outbox 为每个逻辑回复固定 msg_seq；网络结果不确定时保持同一序号做有界重试并记录未知状态，不递增序号造成重复回复。主动发送不假设具有同样去重保证。
12. **失败语义**：检查 HTTP 状态与对应业务错误码，区分 Token 接口 code 与 OpenAPI err_code；鉴权失败受控刷新、限流有界退避，权限／格式／违规／回复过期不无限重试。不把 API 受理或审核中当成用户已收到。
13. **外部服务**：统一异步 HTTP 客户端、超时、并发上限与关闭流程；慢调用在 worker 中执行，不阻塞回调。记录必要 trace_id、功能编号与失败类别，而非完整消息。

| P2 可靠性与业务基础 | inbox／outbox、重启恢复、并发／限流、显式命令路由与业务服务边界；补测试 | 合成／脱敏样本覆盖重投、并发、崩溃恢复、错误码、Token 过期、回复过期和未知发送结果 |

| P4 小范围试运行 | 明确目标群、发送方开关、指标与观察窗口；限制群范围 | 不发生新旧双回复；达成维护者确认的成功率、延迟、限流与可观测性门槛；未编造数值 |
| P5 正式切换与清理 | 停旧发送／客户端依赖，切换部署，验证后去掉旧入口、导入、依赖与配置 | 全新环境只安装新依赖即可启动与测试；运行链路无 NoneBot／OneBot；README、部署、告警与回退一致 |

P1 与 P2 可在同一实现任务中完成，但一次回复成功不代表达到生产可靠性。各阶段时长与切换日待确认，不把建议进度写成承诺。
