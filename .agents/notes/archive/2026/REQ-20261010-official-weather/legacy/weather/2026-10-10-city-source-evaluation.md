## 1. 目标、当前事实与非目标

目标：区分官方可下载城市列表与 GeoAPI 返回数据的许可；核实可落库的开放城市源、坐标／中文搜索可用性，给出后续设计和验收门槛；将调用上限更正为月度免费预算。

当前 旧入口（历史路径 `bot.py`，已清理）、旧天气模块（历史路径 `src/plugins/weather/__init__.py`，已清理） 未改造，尚无本地城市库、官方 QQ 连接或天气调用预算实现。工作区原有业务和配置改动均保留。

非目标：本阶段不将第三方城市数据存入项目、不建立城市数据库，不批量调用 GeoAPI，不读取真实凭证、连接 QQ 或调用天气 API，不把公开许可视作准确性／全部法律合规保证。公网数据只在内存中用于字段审查，未保存第三方数据副本。

## 3. 官方 LocationList：实际技术核查

### 3.1 固定核查版本与来源

- 官方下载入口：[常见城市列表](https://dev.qweather.com/docs/resource/location-list/)。入口说明信息不定期更新，优先使用 GeoAPI 获取最新信息。
- 仓库：[qwd/LocationList](https://github.com/qwd/LocationList)。
- 本次核查提交：`bf62f4934f9b2e8260d8a49ee0cf8eb8a948eda3`，其提交时间为 2025-11-28；这是本次查询返回的最新提交，不等于每条城市记录的更新时间。
- [固定版本 CSV 元数据／内容](https://api.github.com/repos/qwd/LocationList/contents/China-City-List-latest.csv?ref=bf62f4934f9b2e8260d8a49ee0cf8eb8a948eda3)，blob 为 `3ee735fa2176d305909c354386ef8e903bcdeee7`。
- CSV 第一行原文版本标记为 `China-City-List v202506200`；不自行纠正或推断它是完整日期。

### 3.2 内存解析结果

通过项目已有 Python 3.12 虚拟环境、httpx 读取公开 GitHub API 返回的 Base64 内容，在内存解码并用 csv.DictReader 解析，跳过独立版本行；未写入数据文件。

已确认字段：`Location_ID`、`Location_Name_EN`、`Location_Name_ZH`、`ISO_3166_1`、`Country_Region_EN`、`Country_Region_ZH`、`Adm1_Name_EN`、`Adm1_Name_ZH`、`Adm2_Name_EN`、`Adm2_Name_ZH`、`Timezone`、`Latitude`、`Longitude`、`AD_code`。

技术注意：CSV 首行不是表头；ID与行政编码保留字符串；使用标准 CSV 解析而非 split 逗号；保存完整来源精度，仅在请求 v1 时按接口要求格式化到两位小数。行政区与中文名共同消歧，不能把区县／城市名称视为全球唯一。

### 3.3 授权判断的边界

[官方页面](https://dev.qweather.com/docs/resource/location-list/)主动提供下载，是与“批量爬取 GeoAPI”不同的来源；不能直接推断该列表一律不能本地使用，也不能直接推断它采用 MIT／CC BY。

本次确认 [仓库根目录](https://api.github.com/repos/qwd/LocationList/contents/) 没有 LICENSE 文件；[仓库元数据](https://api.github.com/repos/qwd/LocationList) 的 license 为 null，读取常见 LICENSE 路径得到404；[README](https://raw.githubusercontent.com/qwd/LocationList/master/README.md)说明城市ID的天气查询用途，但未给出开放许可条件。

以上是“未找到所需明确许可”的证据，不是法律上全面禁止使用的结论。应向和风确认：在本项目本地落库／建立名称索引、只供本服务查询、处理更新、修改别名及把数据随源码／镜像发布分别是否允许，需保留何种声明。不要将公开CSV的许可推广为 GeoAPI 返回数据许可。

开发者许可协议页面已访问，但文本抽取只取得网页壳，没有取得协议正文；不得把未读取的具体条款写成已核实结论。

## 4. GeoNames：明确开放许可与技术限制

### 4.1 许可来源

- [GeoNames 数据导出与使用条款](https://www.geonames.org/export/#terms)：数据免费、CC BY、商业使用允许；需链接或其他方式注明 GeoNames；不保证准确、及时或完整。
- [导出文件 README](https://download.geonames.org/export/dump/readme.txt)：明确数据适用 CC BY 4.0，UTF-8制表符格式。
- [GeoNames 介绍](https://www.geonames.org/about.html)：数据可下载，多语言，所有经纬度为 WGS84。
- [CC BY 4.0 许可正文](https://creativecommons.org/licenses/by/4.0/legalcode.en)：第2节允许复制、分享、修改，第3节要求归因、许可链接和变更说明，第4节包含数据库内容提取／复用。

建议在数据来源说明、程序帮助与数据输出的适当位置保留 GeoNames／来源链接／CC BY 4.0／本项目筛选或修改说明；不声称 GeoNames 为项目背书。归因义务与和风天气数据自身的来源声明分开处理。上述是许可文本核查摘要，不替代其他适用法律、地名／地图展示或个人信息合规要求。

### 4.2 数据选择与边界

官方 README 提供各国 `XX.zip`、`cities500.zip`、`alternateNamesV2.zip`、行政编码表、时区与增量删除／修改文件：

- 首版只服务确认的地区时，可从国家／地区数据中筛选居民点与必要行政记录，不先下载全部全球数据。
- `cities500` 是人口超过500的城市或一定级别行政驻地子集，**不是完整中国行政区字典**；不能据数量较小认定它覆盖所有区县与用户城市。
- 多语言名称使用 alternateNamesV2 及其语言／优先／历史标记；中文名和简繁别名必须检查真实样本，不把主名称默认为中文。
- 用 [feature codes](https://www.geonames.org/export/codes.html)区分居民点、行政区、历史名称与其他地理对象；不要对山峰、同名河流等自动返回“城市天气”。
- 保持原始 geonameid、行政层级和坐标来源。GeoNames ID 不是和风 Location_ID，不可互换；坐标可直接用于和风 v1，不需要伪造和风城市ID。
- 城市点／行政区代表坐标的含义不同，行政区代码也不能直接等同中国官方区划码。通过地图或获准权威资料验证坐标，不声称区级网格预报代表整个行政区。
- 本次未下载 GeoNames 数据包或抽样数据，因此中文覆盖、同名消歧、坐标质量、性能和实际导入量仍未验证。官方文档给出每日导出／增量，但更新频率不等于行政变更即时完整。

## 5. 推荐后续边界与查询流程（尚未实施）

```text
QQ 独立 WebSocket 接入
  → 天气命令（用户主动输入）
  → CityResolver（独立城市来源）
       ├─ 已批准的本地许可数据：检索、行政区消歧、坐标
       └─ 未命中：GeoAPI实时查询，返回信息不长期落库
  → 有效预报缓存？
       ├─ 是：显示数据时效与来源
       └─ 否：持久化月预算占位 → 和风v1坐标预报 → 缓存 → QQ被动回复
```

拟议存储边界：许可城市表／别名表、用户自有输入与可删除偏好、来源版本与许可声明、天气缓存、月预算，分别管理。只存命令所需数据，不存全部群聊。来源字段包括 provider、source_id、版本／获取日期、许可和变更说明，避免把 GeoAPI 回包塞入许可数据表洗成开放数据。

使用坐标格式化到两位小数后的值作为实际请求位置；缓存键至少包含来源许可范围内的位置、v1版本、天数、语言、本地时间选项。初期天气缓存可约1小时，按查询地点跨日失效，显示来源与时效；不能以天气缓存为名建立 Geo 返回坐标／城市名称索引。

需要验收的关键样本：北京／区县、中文名重名（如朝阳）、直辖市层级、少数民族地名／简繁与英文别名、县级与乡镇覆盖、行政区变更、坐标边界、时区／跨日。样本清单是建议，不伪造命中结果。

## 6. 已确认月预算与免费保障边界

维护者明确更正为**每自然月合计不超过50,000次免费份额**。此前每日50,000的说法不再作为当前需求，不能保留按日清零作为主保障。

后续实现应对所有和风外发请求统一管理，Geo搜索、预报、未来统计／探活和每次重试在发送前原子占用持久化预算；失败、超时不回退，本地命中不计外发。重启／并发／凭据轮换不重置额度；存储不可用时拒绝外发；耗尽后只返回仍有效缓存或“月额度已用尽”。

帐号其他应用／凭据与此前已用量共享官方免费份额。部署前需确认当月初始已用量和预留消耗；供应商统计有延迟，不能只靠定时读统计API作为硬闸。单一服务从零计数不证明全帐号仍有50,000可用。

账单自然月重置时区尚未核实，不能从小时统计UTC或用户界面时区推导；取得确认后配置月边界，在此之前使用更保守的跨月预算策略而非盲目清零。严格本地尝试计数可能少用免费额度，但不会故意以不确定调用结果返还额度。
