## 1. 背景与当前事实

[项目配置](<../../../../../../../pyproject.toml>)声明直接依赖，[uv锁文件](<../../../../../../../uv.lock>)固定解析结果；常规环境使用uv同步。根目录 `requirements-export.txt` 是此前从锁文件导出的pip兼容格式清单，不是应用运行时的依赖来源。维护者明确后续只用uv，不通过pip安装依赖。

## 2. 目标、非目标与验收条件

- 目标：移除不再使用的 `requirements-export.txt`，使当前README、开发约定和部署指南明确依赖仅由uv管理，并记录清理决策。
- 非目标：不改变 `pyproject.toml` 中的依赖、`uv.lock` 的解析、Python版本、运行入口、代码或虚拟环境。
- 验收条件：导出清单不再存在；当前指南不再要求生成或使用pip兼容依赖清单；历史记录保留当时执行事实并能指向本记录；差异格式检查通过。

## 3. 方案摘要与关键决策

依赖新增／升级继续以 `pyproject.toml` 为声明源、`uv.lock` 为锁定结果，执行 `uv lock`、`uv sync --locked` 和离线验证。删除 `requirements-export.txt` 与 `uv export` 操作说明，不改依赖本身。`uv pip check` 仅是uv提供的环境一致性检查命令，不用于安装依赖，继续保留。

风险是外部部署脚本若仍运行 `pip install -r requirements-export.txt` 将无法使用；这与维护者决定的仅uv管理方式一致，今后应改用uv命令，而不是继续保留该兼容入口。
