# 需求中心的过程记录迁移与生命周期

## 需求与确认来源

维护者在本会话要求将过程文件从 docs 迁至 .agents/notes，按需求关联多轮会话的提案、实施与驳回；需求处理完毕在收尾提交时整包归档，归档仅供历史查询，不可作为当前决策依据。维护者明确同意按需拆分，无须 Obsidian 兼容，无代码交付也可按相同流程收尾，并授权开始实施。历史“整理项目文档与迁移规划”会话仅为背景。

## 目标、非目标与验收

- 建立需求包、稳定 ID、标签／类型关联、统一模板与活跃／历史索引。
- 分类迁移已有过程记录，保留正式部署与使用文档，固化现行规则并修正引用。
- 验证迁移完整性、相对链接及变更范围；不修改业务代码、依赖、数据库或私有配置，不运行真实服务，不自动暂存或提交。
- 旧记录不能证明当前需求完成；无法确认的旧需求保持待核实。归档不宣称已上线或已提交。

## 提案（proposal）

小需求一个 index.md；复杂需求按需拆分。提案／实施／驳回作为类别共存，需求状态与批准状态独立。普通 Markdown 链接＋元数据支持检索，无特定软件依赖。

## 决策与驳回（rejection）

| 对象 | 决定 | 原因与确认来源 | 适用条件／替代方向 |
| --- | --- | --- | --- |
| 按会话／日期重复建档 | 不采用 | 维护者指出记录增长与展示干扰 | 同目标及验收范围复用稳定需求ID |
| 永久保留驳回并注入上下文 | 不采用 | 维护者强调业务时效性及整包归档 | 活跃期按相关性读取，归档后不生效 |
| 全量将 docs 搬走 | 不采用 | 双方确认过程与正式文档职责不同 | 部署、使用和公开参考资料保留 |
| Obsidian专用语法依赖 | 不采用 | 维护者明确仅举例 | 普通Markdown与YAML元数据 |

## 实施（implementation）

- 建立[记录规则](<../../../README.md>)、[统一模板](<../../../templates/task.md>)、[未归档需求索引](<../../../INDEX.md>)及[历史入口](<../../INDEX.md>)；支持稳定ID、标签、类型关系、按需拆分和整包收尾。
- 将33个旧过程／附件文件归组迁移：32个文件进入16个旧需求包，旧模板进入本包历史附件；加上本需求共17包。不按模块或会话机械建包，跨模块首交付及四表设计各聚为一包。
- 15个已结束的旧需求标记 `ready-to-archive`；多实例保持 `proposed`／`pending`。本需求完成后同样待归档，因此最终为16个待归档包、1个待批准包。没有推断历史提交，也没有使用首次迁移例外提前归档。
- 旧材料加历史提示、修正相对链接，保留原事实与旧时间语境；旧TOML只含注释，按原字节保留，旧路径不作当前导航。归档和迁入的历史正文均不是当前决策、默认实施上下文或负面提示来源。
- 正式文档区保留7份文件；[开发规范](<../../../../../AGENTS.md>)、[项目说明](<../../../../../README.md>)、[正式索引](<../../../../../docs/README.md>)、[部署指南](<../../../../../docs/qq-integration/2026-10-10-deployment.md>)、[路线图](<../../../../../docs/project/2026-10-10-roadmap.md>)及[天气参考索引](<../../../../../docs/weather/reference/README.md>)同步职责与引用。已固化模块边界、uv、直连／JWT、预算与接收发送可靠性、四表默认永久保存、AppID暂缓等现行规则，不以旧稿维持规则效力。
- 工作区原有暂存／未暂存／未跟踪修改均保留；未操作Git索引，未修改业务代码、依赖、运行配置或数据库。使用标准库进行文档批处理与验证，不安装依赖。
